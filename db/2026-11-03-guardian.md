## What it does

Adds a parent / guardian to a client's profile, so a dojo student (usually a child) can be added with the parent's details
and fee reminders go to the parent on WhatsApp:

- `guardian_name`: the parent's name
- `guardian_phone`: the parent's phone, stored like `phone` (international format, `+919876543210`, via `clientPhoneValue` in `lib/phone.ts`)
- `guardian_relation`: Mother / Father / Guardian

Every existing row gets `null`, so nothing changes for anyone until a parent is entered. The columns are not limited to
martial arts companies: an adult gym member can have a parent too (the Add Member checkbox only starts ticked for dojos).

The Business type picker (Super Admin, same PR) needs **no SQL**: `companies.business_type` already exists. The Mumbai
check rules on `companies` (listed in `db/2026-11-01-multi-country.md` Step 0) are `companies_country_check`,
`companies_company_type_check`, `companies_partner_limit_check`, `companies_slug_format` and
`companies_base_currency_allowed`, so nothing limits `business_type` to the old values and `martial_arts` saves as is.

## Policies and triggers (checked, nothing to change)

Checked against `db/2026-10-30-rls-hardening.md` (rules) and `db/2026-11-01-multi-country.md` Step 1a item 5
(the latest `protect_profile_columns()`, matched live on 2 Nov).

1. **RLS covers the new columns.** The `profiles` rules (`iso profiles select / insert / update / delete`) are row-level:
   they decide which rows a role can touch, not which columns. "iso profiles update" lets owners and partners update
   **clients of their own gym**, and super admin every row, so they can set the guardian fields. In practice the app
   writes them through the server (`create-user`, `update-client`, secret key), which RLS doesn't affect; those routes
   check the caller with `getCaller(STAFF)` + `checkCanManageClient`. **Result: OK, no change.**
2. **`protect_profile_columns` doesn't block staff.** It returns early for server calls (`auth.uid() is null`) and super
   admin, blocks `role` / `company_id` for everyone else, and for **clients and coaches** only blocks `client_type`,
   `archived_at`, `primary_coach_id`, `country`, `currency`. Owners and partners aren't in that last check, and the
   guardian columns aren't in it at all. **Result: OK, no change.**
3. **A client can edit their own guardian fields.** "iso profiles update" allows `id = auth.uid()`, and the trigger
   doesn't list the guardian columns, so a client who logs in could change their own parent details from the browser
   (the client app has no screen for it). **Noted and left as it is for now.** If it's ever needed, the fix is to add
   `guardian_name / guardian_phone / guardian_relation` to the client block of `protect_profile_columns()`.
4. **Coaches can see `guardian_phone`.** "iso profiles select" lets a coach read whole rows of their gym's **PT clients**
   (there are no column grants on `profiles`), so a coach can read a PT student's parent name and phone. Fine for now:
   dojo coaches get their own view in Build 3.
